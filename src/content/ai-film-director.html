《HELL GRIND》
製作工作流研究 / Case study

第一次看到 Higgsfield Studio 公開《HELL GRIND》的製作專案時，我感興趣的不是「他們用了什麼神奇 Prompt？」

一部 AI 長片，到底是怎麼被管理與製作出來的？

於是，我開始研究公開 Project 裡的 Assets、Prompts、Generations，以及角色、場景與道具之間的 Reference 關係。

我原本以為答案是
「更好的 Prompt」。
後來發現，真正需要管理的是世界。

不是一張參考圖。
是一套製作資產。

Characters 是能反覆調用的角色資產。Environments 是有方向、地標、視角與狀態的空間。Props 是能跨鏡頭追蹤的道具。

角色不能突然變臉，上一鏡受的傷不能消失。鏡頭轉到房間另一側，門窗與家具也不能重新長一次。

如果 AI 電影管理的是世界，為什麼每個鏡頭還要重寫一次世界？

AI Film Director 把這些製片原理重新抽象成通用工作流。它不是 Hell Grind Prompt Pack，也不是 Higgsfield 專用工具。

Production State 才是真相。

Prompt 是根據當前製作狀態編譯出來的結果。故事、資產、世界與鏡頭資訊分開管理，生成後再把選用版本的結束狀態傳遞下去。

前期規劃Story → Scenes / Shots

故事節拍、鏡頭拆解、時間預算與穩定 ID。

製作狀態Assets → World State

角色、場景、道具，以及跨鏡頭延續的狀態。

鏡頭編譯GEO → Acting → Camera

空間與走位、可觀察表演、攝影意圖，交給 Prompt Compiler 與 Model Adapter。

生成與剪輯Generation → QC → Edit

記錄版本、檢查實際媒體、選用片段、回寫連戲狀態與剪輯計畫。

角色穿什麼？站在哪裡？看著誰？光從哪裡進來？這些答案存在於 World State，而不是散落在某一條 Prompt 裡。

一致性，
不只是臉不要變。

角色身分與角色狀態分開維護。同一個人可以淋濕、受傷或換裝，仍然保留相同的 Character Identity。

  • Identity角色的固定身分與識別
  • Appearance外觀特徵與參考
  • Wardrobe / State服裝、傷勢、濕度、持有道具
  • Voice / Behavior說話節奏、呼吸、眼神、步伐與壓力反應
觀眾是否相信，
這一直是同一個人？

從「同一張臉」走向「同一個角色」。把情緒與戲劇意圖，轉成能在鏡頭中看見的表演。
